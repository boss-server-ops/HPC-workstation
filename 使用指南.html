HPC Claude 工作看板使用指南

版本：Windows 分享版 1.1.0

1. 你会得到什么

浏览器中的项目看板和 SSH 终端，可以继续远端已保存的 Claude Code 会话。关闭网页只断开查看窗口，由看板启动的 Claude 保留在远端 tmux 中。远端机器重启、管理员清理进程、作业被调度器结束，仍可能终止运行；届时可从已保存历史恢复。

每个人用自己的 Windows 配置、SSH 身份、Linux 账号和 Claude 登录信息。分享包不含发布者的服务器地址、SSH 配置、密码、私钥、API Key、项目目录或会话历史。

2. 安装前准备

Windows 电脑

  • Windows 10/11 的 64 位系统。x64 已验证；ARM64 依赖有预编译包，但本版本未在 ARM64 设备上验证。
  • 从 https://nodejs.org/ 安装 Node.js 22 或更新的 LTS，保留 npm 与 PATH 选项。安装后重新打开安装程序。
  • 在 Windows「设置 → 可选功能」确认 OpenSSH 客户端 已安装。
  • 首次安装需访问 https://registry.npmjs.org/ 下载依赖。平时只需能访问自己的 HPC 或跳板机。

Linux HPC

你的账号需要可用的 python3（3.6+）、tmux、bash、claude，且 Claude 已经完成自己的登录或 API 配置。在允许交互任务的节点上使用，并遵守集群的资源使用规则。

HPC 登录需要 SSH 密钥或已解锁的 SSH agent。网页可输入的是跳板机密码；它不提供 HPC 密码、HPC 多因素认证或私钥口令的交互输入。HPC SSH 服务目前按 22 端口配置；跳板机端口可自定义。

3. 配置自己的 SSH（只需做一次）

在自己的 %USERPROFILE%\.ssh\config 中添加一个别名。下面的地址和用户名全部是示例：

Host my-hpc
    HostName 192.0.2.10
    User researcher
    Port 22
    IdentityFile ~/.ssh/id_ed25519
    IdentitiesOnly yes

把地址、账号和密钥路径改成你的。将自己的公钥按学校流程安装到 HPC，私钥始终留在自己电脑。如果密钥有口令，先按系统的 SSH agent 流程解锁。

第一次连接需要确认 HPC 主机指纹。请向管理员核对后，在 PowerShell 运行一次：

ssh -o HostKeyAlias=192.0.2.10 my-hpc

进入后确认这些命令可用：

python3 --version
tmux -V
claude --version

退出远端后，用下面的命令确认无需交互输入就能登录：

ssh -o BatchMode=yes -o StrictHostKeyChecking=yes -o HostKeyAlias=192.0.2.10 my-hpc "echo SSH_OK"

如果只能从校外跳板机进入，首次确认 HPC 主机密钥时增加 -J jumpuser@198.51.100.20。此步骤可能分别要求跳板密码或密钥认证。看板的连接通道会覆盖 SSH 配置中的 ProxyJump/ProxyCommand，因此网页切换通道不会受原配置的跳板设置干扰。

固定节点很重要： nodeAddress 必须指向一台固定机器，不能用随机分配节点的负载均衡入口。host 别名主要提供你的 User、IdentityFile 等 SSH 选项，实际连接地址由网页配置指定。

4. 安装和启动

  1. 完整解压 ZIP。不要直接在压缩包预览窗口内运行，也不要放在只读目录。
  2. 双击 Install.cmd。它检查依赖、执行 npm ci、测试 Windows 终端组件，然后记录本机 Node 路径。
  3. 安装成功后自动打开网页。桌面快捷方式可日常启动；Windows 登录启动快捷方式会静默运行后台，不自动弹出浏览器。

安装器不需要创建系统服务或存储 Windows 密码。标准用户可以写入自己的安装目录和快捷方式即可。

若不需要登录启动，可在解压目录的 PowerShell 运行：

powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Install.ps1 -NoAutoStart

若默认的 43127/43128 端口被其他应用占用，安装器会提示，不会终止其他程序。选择两个不同的空闲端口：

powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Install.ps1 -Port 43227 -StatusPort 43228

此时网页为 http://127.0.0.1:43227/。移走安装目录、升级 Node 路径或重装依赖前，先运行 Uninstall.cmd 或 Stop.cmd；在新位置重新安装快捷方式。更换端口时重新安装需要继续指定端口。

5. 网页首次配置：校内或 VPN

点击「配置我的服务器」，把下面的 JSON 改为自己的值：

{
  "host": "my-hpc",
  "nodeAddress": "192.0.2.10",
  "hostKeyAlias": "",
  "connectionMode": "direct",
  "jump": { "host": "", "port": 22, "username": "", "fingerprint": "" },
  "nodes": [],
  "claude": { "command": "claude", "configDir": ".claude" }
}
字段 填什么
host 本机 SSH 配置中的别名，例如 my-hpc
nodeAddress 固定 HPC 节点地址
hostKeyAlias 通常留空，即按节点地址核对 known_hosts；如管理员有专门的主机密钥别名，可填写它
connectionMode direct 表示校内/VPN，jump 表示校外跳板机
jump 只走直连时保持空；使用校外时按下一节填写
nodes 初次保留 []，由「验证并登记节点」读取并保存节点身份
claude.command 默认 claude。可填在远端 .bashrc 中定义的命令或 shell 函数名，不带参数
claude.configDir 默认 .claude，相对远端家目录；也支持绝对路径，例如 /home/researcher/claude-work

配置中不要填私钥、密码或 API Key。保存接口仅保留上述允许的字段，未知字段不会作为连接凭据保存。

依次点击：保存配置 → 验证并登记节点 → 读取我的项目。验证通过 SSH 读取主机名与 /etc/machine-id，不启动 Claude。完成后会从你的 Claude 资料目录索引历史项目。每个项目目录最多读取最近 30 个会话文件，较早的会话需要使用原始 Claude 会话选择功能查找。

自定义 Claude 命令必须尊重传入的 CLAUDE_CONFIG_DIR，不能在函数内改为别的账号目录。这个版本每个安装使用一个资料目录。不要让多个安装以同一远端 Linux 账号同时配置不同的资料目录；远端辅助脚本和 profile 配置按 Linux 账号共享。

6. 校外：配置跳板机

保留同一 HPC 别名和固定节点，把 connectionMode 改为 jump，按自己的跳板机填写：

"jump": {
  "host": "198.51.100.20",
  "port": 22,
  "username": "jumpuser",
  "fingerprint": "SHA256:这里替换成管理员提供的43位指纹"
}

这段只是 JSON 中的 jump 字段；不要直接替换整个配置。示例指纹故意不可用，必须填管理员确认的真实值。管理员可在跳板机上用 ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub -E sha256 等方式提供指纹。不要直接信任未经核对的 ssh-keyscan 结果。

依次点击：保存配置 → 登录校外跳板机 → 输入自己的跳板密码 → 验证并登记节点 → 读取我的项目。

跳板机需允许转发到 HPC 的 22 端口。密码仅用于本次认证，不写入配置或日志；通道断开、本地服务重启后需重新输入。目前网页跳板认证使用密码，不支持跳板机 MFA/纯密钥认证。

之后使用网页顶部「校内 / VPN 直连」或「校外 / 跳板机」切换。切换只重建访问通道，远端 tmux 会话保留。跳板认证成功仅说明第一段连接成功，跳板机到 HPC 的网络也必须连通。

校园客户端的 SOCKS5 连接

如果校园客户端提供本地 SOCKS5 端口，在服务器配置中添加 "proxyPort": 1080，并把 connectionMode 改成 proxy。端口按自己的客户端设置，节点必须填写 IPv4 地址。先连接校园客户端，再保存配置、验证节点并读取项目。网页顶部可切换「校园 SOCKS」。

这是看板到 HPC 的 SSH 通道，不会修改全局网络，也不等于服务器访问 Claude API 的出口代理。若只能通过 SOCKS 登记首次主机密钥，请使用支持该 SOCKS 的 SSH 客户端核对并写入 Windows OpenSSH 的 known_hosts，或在校园网中完成首次登记；看板不会自动信任未知主机。

7. 多节点与重复会话保护

如果历史会话可能在其他节点运行，先在 nodes 中增加它们的固定地址：

"nodes": [
  { "address": "192.0.2.10" },
  { "address": "192.0.2.11" }
]

对已经验证过的节点，保留自动生成的 hostname、machineId 等字段；不要拿此示例覆盖已有身份。保存后在「待验证节点」逐个填地址并验证。添加节点后若使用校外通道，需要重新登录跳板机。每个节点都要能使用该 SSH 别名中的同一账号和密钥登录，且这些节点应共享同一 Linux 家目录和 Claude 会话资料目录。

看板会核对 PID、进程启动时间、机器身份与会话占用记录，并通过原子占用记录防止看板并发重复拉起同一条会话。找不到节点、节点不通、身份变化或无法判定占用时，会阻止新启动。请先恢复连接或核实身份，不要直接删占用记录。它不能约束所有外部终端手动启动的 Claude；发现冲突后会保守处理。

8. 日常使用

  • 继续上次 / 历史会话： 优先接回仍运行的原 tmux；已退出的会话可从已保存的历史恢复。
  • 关闭网页 / 关闭终端标签： 断开本地查看，远端 tmux 和其中的 Claude 继续运行。
  • 只读： 另一个网页正在输入，或检测到同一会话重复实例。前者可以「接管输入」；后者使用「找回旧会话」，预览后选择要保留的实例。
  • 重连： 修复浏览器到原远端进程的连接。若进程本身卡住，重连仍会回到同一进程。
  • 重启当前会话： 先显示将结束的进程，确认后结束它，再从同一会话的已保存历史恢复。未完成的请求可能中断；该操作不会由普通重连自动触发。
  • 复制： 按住 Shift 拖选文字，再 Ctrl+C；没有选中文字时 Ctrl+C 仍用于中断终端任务。也可用工具栏「复制」。
  • 粘贴： 先点击终端，再 Ctrl+V；浏览器剪贴板权限受限时，用工具栏「粘贴」打开输入框，粘入文字后点击插入。多行文字不会自动附加 Enter。
  • 滚动历史： 鼠标放在终端中滚动会进入 tmux 历史，回到底部或退出 tmux 复制模式后继续输入。另有浏览器终端缓冲区；原会话完整历史保存在远端 Claude 资料目录中。

在普通 SSH 终端中启动、没有 tmux 托管的旧进程，无法无损接入网页。先回原终端正常退出 Claude，再由看板恢复同一历史；看板不会因此偷偷启动第二份。

文件管理、拖放上传和下载

点击侧栏「文件管理」，在独立页面浏览远端目录。先进入目标目录，再拖入文件即可自动上传。支持多文件依次上传、进度显示和取消，单文件上限 20 GiB，同名文件拒绝覆盖；整个目录请先打包。进度显示「HPC 已保存」后才算成功，上传时保持网页及网络连接。

文件列表可下载、复制单个或多个路径，也可新建文件夹。文件操作沿用当前 SSH 通道和账号权限。连接新服务器前需先保存配置并验证节点。

9. 故障排查

表现 检查和处理
网页打不开、连接被拒绝 双击 Start.cmd；确认安装成功以及使用了正确端口。查看 data/launcher-error.log、data/server-error.log、data/supervisor.log
安装找不到 node/npm/ssh 安装 Node LTS 和 OpenSSH；重新打开安装程序，使 PATH 生效
npm ci 下载失败 确认 npm registry 可访问，按所在网络要求配置自己的代理，然后重新安装；不要复制他人的 node_modules
首次显示配置弹窗 正常。这是空配置分享版，需要填写自己的服务器
Permission denied (publickey) 检查 SSH 别名中的 User/IdentityFile、公钥授权和 agent 是否解锁；先通过第 3 节 BatchMode 测试
Host key verification failed 按网页使用的 HostKeyAlias（默认固定节点地址）核对并登记正确主机密钥；不要关闭主机密钥检查
跳板指纹不匹配 向管理员确认实际使用的主机密钥算法和指纹，核实后修改；不要随意跳过
跳板已登录但 HPC 超时 检查跳板到固定节点的 22 端口和校园网络；也可在校园网/VPN 下切换直连
节点身份变了 与管理员核实是否重装、地址变化或使用了负载均衡地址。确认后重新配置并验证，程序不自动覆盖旧身份
重连后仍卡住 重连保留原进程；先检查是否停在 tmux 历史/选择模式。确实需要重启时用带确认的重启入口
只看到部分历史 确认 claude.configDir 与原来一致；索引限最近 30 个文件，并过滤子代理记录
新会话启动后立即退出 确认远端 bash、tmux、Claude 命令与登录配置有效；自定义 shell 函数应在交互 bash 的 .bashrc 中可用

本地 supervisor 会在本地服务异常退出后自动拉起它，不会因此重启远端 Claude。Windows 注销/关机期间本地网页不可访问，下次登录后后台入口会恢复；远端进程是否继续取决于 HPC 本身。

10. 数据、卸载与再次分享

  • 本机 data/config.json 保存自己的服务器设置、星标等；data/snapshot.json 保存项目及会话摘要；日志可能带有自己的路径/诊断信息。
  • SSH 私钥、known_hosts 在自己的 SSH 环境，Claude 登录凭据在远端。安装包不会修改或复制这些凭据。
  • 远端辅助脚本写入 ~/.local/state/hpc-claude-board/runtime-v3/，保护记录位于同一父目录的 session-owners/，tmux 使用 hpc-claude-board server。不要在会话运行中删除它们。
  • Stop.cmd 只停止此安装目录的本地看板；Uninstall.cmd 还移除它的快捷方式。二者都保留远端会话及本地数据。
  • 若要彻底清除本地数据，先卸载并确认备份需要的配置，再手动删除解压目录。卸载不登录远端执行清理。
  • 发给别人时使用原始发布 ZIP。开发者也可以运行 node package-release.mjs，它仅打包明确列出的源文件和指南，自动排除 data、node_modules、日志和 SSH 文件，并生成 SHA256 清单。

11. 开发与验证

在安装好依赖的目录运行 npm test 验证配置、HTTP 首次启动、连接参数、复制粘贴、只读保护、重连和 supervisor。若本机也有 Python，可运行 python -m unittest discover -s test -p "test_*.py" 验证远端索引/保护逻辑。

本版本在 Windows x64 验证了干净依赖安装、首次配置网页、Windows PTY 和本地后台恢复；不会使用发布者的实际 HPC 会话做分享版测试。不同集群的 SSH 策略、Claude 版本和节点共享目录方式，需要使用者按本文自行配置并验证。
